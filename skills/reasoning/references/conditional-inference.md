# Method card: conditional inference

Use with [shared rules](shared-rules.md). Lineage: elementary conditional logic and the faithful-reconstruction/contextual cautions in [argument research](lineage.md). The procedure is our synthesis for basic logical checking, not a formal proof engine.

## Trigger and omission

Use when an if/then relation, necessary/sufficient condition or equivalent rule is being used to establish a consequential conclusion. Do not infer a logical defect simply because the argument is informal, uncertain or explanatory. Skip the full card for a settled conclusion or when another adequate route already answers the scoped question and this route need not be assessed.

## Inputs and prerequisites

Retain the exact conditional rule, offered observations and claimed conclusion, including all relevant premises. Fix consequential meanings, quantifiers, negations and strength. Distinguish a statement of what guarantees an outcome from one that only makes it more likely. If meanings or premises visibly conflict, identify the issue or preserve separate readings; do not issue a validity verdict under an unresolved interpretation. No exhaustive consistency search is promised.

## Operation

1. Reconstruct the proposed dependency faithfully. Mark a reverse implication or other missing bridge as an additional premise, not something the original rule supplied.
2. Identify the intended standard: certainty from the stated premises, or a candidate/likely explanation supported by evidence. Use the relevant standard from the shared rules.
3. For a basic deductive claim, inspect the inference. For example, “if A then B; A; therefore B” is valid under that rule, while “if A then B; B; therefore A” is not established by those statements alone. Check whether additional supplied premises change this result.
4. If showing a defect, give a concrete possible case satisfying the retained premises while denying the conclusion. Check that case against each relevant premise and the same meanings. A possible case is not a claimed observation of what actually happened.
5. For an explanatory claim, do not substitute the deductive verdict for evidence appraisal. Ask whether the observation distinguishes the explanation from material rivals and how strongly it supports the proposed scope.

## Warranted result and verification

State which inference holds, fails or remains unresolved and under which premises/interpretation. A verified counterexample refutes the offered entailment; it does not establish the conclusion is false. Failure to find a counterexample does not establish validity. Independently check support for the premises where the task requires a real-world conclusion.

For affirming the consequent, the name describes inferring A from B using only “if A then B.” Use the label only after establishing that defect at the strength actually claimed. “A could explain B” is not the same claim as “B proves A.”

If an explicit reverse rule is supplied—B only occurs when A—and its application to the observations is adequately supported, do not accuse the argument of the original error. A valid inference with uncertain premises remains conditional; do not call it an unconditional factual finding.

## Consequence, correction and stopping

Preserve an adequately supported result. Otherwise identify the missing bridge, narrow certainty to a justified candidate explanation where warranted, or leave the conclusion unresolved. Do not invent a reverse rule or silently validate a repaired argument as the original. Reuse the result in later cards; when a relevant premise changes, reconsider its dependents. Stop after resolving the requested inference unless the task also requires another support route or action choice.
